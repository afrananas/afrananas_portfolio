# SEO and metadata architecture

> Status: Accepted · Owner: Afran Anas · Last updated: 2026-10-13

The main SEO goal is simple: **rank first for the owner's name, and produce clean previews when links are shared.** There is no keyword strategy beyond writing accurate, specific content.

## `<head>` composition

`BaseLayout` renders the whole `<head>` from one typed `meta` prop. Pages never write `<head>` tags themselves.

```ts
interface PageMeta {
  title: string;            // page title, without the suffix
  description: string;      // 70–160 characters
  path: string;             // e.g. '/projects/video-analytics-pipeline'
  ogImage?: ImageMetadata;  // falls back to /og-default.png
  noindex?: boolean;        // /privacy, 404
  type?: 'website' | 'article' | 'profile';
  jsonLd?: object;          // Person on home and about
}
```

| Tag | Value | Requirement |
|---|---|---|
| `<title>` | Home: `Afran Anas — Software Engineer (Backend · AI · Full-Stack)`. Others: `{title} — Afran Anas`. Built by `buildTitle()`. | FR-META-01 |
| `meta[name=description]` | `description`. For projects this is `summary`, and for pages it comes from the `pages` frontmatter. | FR-META-01 |
| `link[rel=canonical]` | `new URL(path, site)` with no trailing slash. Home is `https://<domain>/`. | FR-META-02 |
| `meta[name=robots]` | `noindex, nofollow` when the page has `noindex` set or `SITE_ENV` is not `production` | FR-META-05 |
| `og:title`, `og:description`, `og:url`, `og:type`, `og:site_name`, `og:image` (absolute URL), `og:image:width`/`height`/`alt` | Taken from `meta` | FR-META-03 |
| `twitter:card` | `summary_large_image` | FR-META-03 |
| `link[rel=icon]` | `/favicon.svg`, plus `/favicon.ico` as a fallback | — |
| `meta[name=theme-color]` | `#0f1115` | — |
| `html[lang]` | `en` | Accessibility |

The `site` setting in `astro.config` is the production origin, for example `https://<domain>`. Canonical URLs and Open Graph URLs always use this origin, even in preview builds, which are `noindex` anyway. TODO(owner): set it once the domain is chosen (Q4).

## Social preview images

| Page | Image |
|---|---|
| Default | `public/og-default.png`, 1200×630 ([visual design system](../02-design/visual-design-system.md#imagery)) |
| Case study | `ogImage` from the project, if present (FR-META-07). Otherwise the default. |

There is no build-time image generation, which keeps the dependency count down. If producing images by hand for every project becomes tedious, revisit.

## Sitemap

- `@astrojs/sitemap` with `filter` excluding `/privacy` and `/404`. Drafts never become routes in production, so they never reach the sitemap.
- Output: `sitemap-index.xml`.
- A build-output check compares the sitemap URLs with the expected set of indexable routes (FR-META-04).

## robots.txt

Generated by `src/pages/robots.txt.ts` from `SITE_ENV`:

```
# production
User-agent: *
Allow: /
Sitemap: https://<domain>/sitemap-index.xml

# development / preview
User-agent: *
Disallow: /
```

## Structured data

- `Person` JSON-LD appears on `/` and `/about` (FR-META-06). It is built by `personJsonLd(profile)` with the fields `name`, `jobTitle` (the positioning line), `url`, and `sameAs` (GitHub, LinkedIn). Every value comes from `profile.ts` and so matches the visible content.
- It is emitted as `<script type="application/ld+json">`. That is a data block, not executed script, so it doesn't conflict with the CSP.
- No other structured data is used. `Article` or `SoftwareSourceCode` markup on case studies would add little and could mislead.

## Content signals

- One `h1` per page, with headings that describe the content (see [accessibility](../02-design/accessibility.md#structure-and-semantics)).
- Every indexable page is reachable through plain links (NFR-SEO-01), and all content is in the HTML (NFR-SEO-02).
- Descriptive link text, and images with meaningful alt text.
- Fast pages (NFR-PERF-*) are also a ranking factor.
